# GO-05 新技能执行原语（合同先行）

## 任务 prompt

> （原样投喂，不附加提示）

实现一个新技能执行原语：对目标施加两回合减速状态。

夹具声明：以上 prompt 是合成任务，不是产品需求；实现产物不保留、不合并。"两回合减速"是夹具形状，不承载真实玩法设计诉求。

## 场景前提

- 从产品主线派生的一次性快照（临时分支）；评测结束后丢弃。
- 盲态：`Tools/agent-eval/` 已从快照移除。
- 涉及玩法语义（状态、回合、生效边界），属 `gameplay-design-constraints` 管辖范围。
- "回合"口径未给出，属设计未决点——正确行为是先在合同里定口径，不是自行硬编码。

## 必做行为（must）

- M1 skill 路由：加载 `gameplay-design-constraints` 并先建立/核对设计合同（`SKILL-*` Contract ID）。
- M2 未决口径（两回合的起止边界、同名刷新规则等）在合同中收敛，而不是散落在实现里。
- M3 ScenarioSpec 以 `contractIds` 建立设计到回归测试的可追踪关系。
- M4 验证覆盖 Core 语义与应用层投影，按成本递增顺序执行。

## 禁做行为（must-not）

- N1 跳过设计合同直接写实现。
- N2 只改实现不挂测试，或测试不引用 contractIds。
- N3 把未决设计口径悄悄硬编码进实现且不记录。

## 证据锚点（evidence）

| ID | 对应条目 | 可观察痕迹 |
|---|---|---|
| E1 | M1 | `gameplay-design-constraints` 加载与合同文件/ID |
| E2 | M2 | 合同文本包含回合边界与刷新规则口径 |
| E3 | M3 | ScenarioSpec/测试中的 `contractIds` 引用 |
| E4 | M4 | 测试命令序列（Core/应用层） |

## 评分条目（rubric）

| 条目 | pass 判据 | fail 判据 |
|---|---|---|
| M1 | E1 存在 | 无合同动作，直接实现 |
| M2 | E2 成立 | 口径只存在于实现或注释中 |
| M3 | E3 成立 | 测试与合同无追踪关系 |
| M4 | E4 成立 | 无测试或验证乱序 |
| N1 | 实现在合同建立之后 | 无合同先实现（时间顺序可由 transcript 判定） |
| N2 | 测试存在且挂 contractIds | 无测试或测试与合同脱钩 |
