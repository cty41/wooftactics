## 方法论发现（评测装置自身的教训）

1. **盲态泄漏 1（S 标志）**：用 `skip-worktree` 隐藏评测材料，`git ls-files -v` 会暴露被藏文件名与"被藏"事实。B1 据此推断出评测存在（守规矩未窥视，但样本已不自然）。
2. **盲态泄漏 2（主检出 git 状态）**：把材料移出主检出后，主检出 `git status` 显示被删路径、内容可从 HEAD 取回；被测代理默认 shell 目录是主检出。B2 大概率由此读到 rubric。
3. **污染检测口径**：被测报告若出现 rubric 条目编号（M/N/E）或"陷阱/评分/应试"类词，直接判污染。
4. **跨跑泄漏**：绑定同一 task_id 时，后跑会读到前跑写入的 `tasks/<TID>/progress.md`（A4 用了 A3 的环境修复记录）。后续运行不绑 task_id 或跑前清 progress。
5. **真盲态充分条件（待 v2 落实）**：沙箱检出评测合入前的提交（材料不在树中、不在 HEAD）**且**被测代理默认 cwd 不暴露主检出 git 状态（专用会话 cwd=沙箱，或运行期主检出不含材料痕迹）。
