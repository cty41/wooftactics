DESIGN BRIEF · 尚未实施

从“记录约束”升级为“执行约束”

Pure Run schema v4 已经能绑定 Brief、Contract、Acceptance Case、SHA 与人工裁决；本次优化将在此基础上增加生图后的独立多模态审核闭环，让明显违反既定规则的候选稳定地无法进入 cty41 的审美审核。

目标不是让 ImageGen 幂等，而是让同一合同下的失败结果以尽可能一致的方式被识别、隔离和修正。

为什么旧状态机会重复犯错

验证了“标注”，没有充分验证“图像事实”

例如 noArms 只会拒绝蒙版中的 arm/leg 标签。图像画出胳膊后，若被误标成 hand/core，仍可能绕过门禁。

几何合规不等于视觉拓扑正确

bbox、中心和三段宽度能发现部分尺寸错误，却不能可靠识别梨形身体、独立腿段、浮空爪或角色身份漂移。

遮挡检查不理解视觉连续性

装备标签面积可以合规，但上下两段在人眼看来仍可能像断裂。旧 Composition 甚至会因设置多个出口而鼓励过度展示装备。

没有自动反馈闭环

技术报告只产生 issue/warning，无法把“唐刀断裂、环首过正、出现四肢”等问题自动转成受约束的 retry delta。

比旧状态机强在哪里

维度现有 schema v4优化后
约束对象主要验证记录、哈希、蒙版与局部几何同时审查实际图像、蒙版诚实性、视觉拓扑与上下文关系
错误发现大量依赖 cty41 首次指出明确合同违反先由独立 Reviewer 拦截
失败处理人工反馈后手动 retry生成结构化 defect、冻结正确项并有限自动 retry
历史经验OKF、文档、案例与 150 条 Feedback 分散存在编译成当前 Job 适用的精简审核政策与正反案例包
装备遮挡常以可见窗口和面积上限描述新增“空间关系优先、零最低展示量、视觉连续性”规则
裁决权限cty41 唯一批准保持不变；模型只能 retry、升级人工或放行给人工

历史知识不再只是文档

Rule Registry

胶囊体、无四肢、爪直接接触、UL 原生投影、后层遮挡、装备克制等稳定规则。

Case Registry

绑定真实 approved/rejected 图片、Feedback、人工理由与 SHA；反例仅供审核。

Compiled Policy

按 family、pose、direction、equipment state 为当前 Job 选择相关规则，避免把全部历史塞进提示词。

Lesson Promotion

当前反馈立即服务当前 Job；只有 cty41 明确授权，才升级为资产、家族或项目级共享规则。

有限自动修正预算

a001 · low发现明确问题即可 retry
a002 · medium复核上一轮修正与回归
a003 · high最后自动轮；仍失败则交人工

每个 Job 总共最多三个“生成＋Reviewer”轮次，不生成 a004。透明边缘等技术重处理不占生图轮次。

权限护栏

模型可以

  • 识别明确 Acceptance Case 违反
  • 指出图像区域和对应规则
  • 生成结构化 retry delta
  • 冻结上一轮正确特征
  • 无法判断时升级给人工

模型不可以

  • 批准或 promote 资产
  • 把审美偏好包装成硬失败
  • 输出综合美学分数
  • 把 rejected 图作为生图输入
  • 修改 cty41 已冻结的规则

本次诗人 UL 会怎样被提前拦截

胳膊与腿复发

Reviewer 直接看候选与蒙版叠加图；即便蒙版声称它们是 hand/foot，也会报告视觉拓扑与标注不一致。

胶囊体漂移

同时比较母图核心轮廓、三段宽度和批准 UL 角色上下文，而不只看校准后的 bbox。

唐刀像断成两截

检查视觉连续性与遮挡可推断性；不再要求露出下方鞘尾，大部分唐刀完全不可见是合法结果。

环首角度过正

将独立批准投影与最终实装视角分别审核；角色遮挡不会成为重新画成正面圆环的理由。

认证策略：优先由 DeepSeek Harness 通过 ChatGPT/Codex OAuth 启动全新 GPT‑5.6 Sol 子 Agent；标准 OpenAI API 仍是未来可选、独立计费的 Adapter。本页描述的是已确认设计方向，不表示功能已经落地。
