# 子代理回执契约与拆分决策规则

## Report

## [S1] 问题

拆给子代理的工作以自由文本总结交回，主循环拿到的是有损 handoff——文章点名的"传话游戏"在本项目的对应物：回执不可核对、格式随跑随变（基线 B1/B2 的报告结构完全不同），主循环只能信任总结。"何时该拆子代理"也没有书面规则，全靠默契，跨会话行为不一致。P2 的拆分试点（OKF 同步链、验证日志分诊）等这份契约落地才敢开。

## [S2] 设计

### S2.1 拆分决策规则（何时拆）

判据主体是**上下文需求与结果紧凑度**，不是任务大小：

**该拆**——
1. 规格已冻结的机械实现（设计合同 `verified_current`、任务书明确、照图施工）；
2. 上下文重、结果紧凑（日志分诊、OKF 同步链、批量审查、大 diff 归纳）；
3. 纯并行独立调研（用完即弃的探索上下文）；
4. 黑盒验证与独立 review（隔离视角本身是目的）。

**不该拆**——
1. 与用户的设计收束（grilling/brainstorming/需求澄清）；
2. 计划撰写（写计划的必须看过全部现场）；
3. 跨层边界未定、中途必然改方案的开放性改动；
4. 需要完整会话上下文的写入决策（OKF 正文落笔、验收账本定性）。

拿不准时默认不拆：主循环串行加载 skill 是安全侧。

### S2.2 回执契约（四段 schema）

子代理交回的回执必须包含四段，缺段即视为不可用：

1. **做了什么**——结论式陈述，≤10 行；
2. **证据**——可独立核对的锚点：命令+输出要点、文件路径+行号、哈希、测试计数；
3. **偏差点**——与任务书的差异、范围外改动、被跳过步骤及原因；
4. **待核验项**——子代理自认为完成、但主循环必须自己验证的声明清单。

规则：**自我声明不算证据**（与 eval kit 评分同源原则）；主循环收到回执后必须对证据锚点至少做一次独立核对（便宜手段：`git diff`、状态查询、抽查命令重跑），未核对的结论不得直接进入后续步骤。评测运行（`Tools/agent-eval/`）遵循其自身 README，不在本规则约束内。

### S2.3 落点

- `.agents/rules/subagent-handback.md`（新）——S2.1 决策规则 + S2.2 回执契约 + 主循环核验义务 + 一个迷你示例回执。
- `AGENTS.md` 当前规则索引补一行。
- 与既有体系的关系：compose-next 的 review 结论格式保持不变（它更细，是本契约在 review 场景的特化）；拆分决策规则不改变 `agent-worktree` 的 worktree 边界。

## [S3] Out of Scope

- 机检校验脚本（`Tools/agent-policy/` 家族，后续与 P3 一起做）。
- P2 拆分试点的执行（OKF 同步链、日志分诊）。
- 对 compose-next、评测 kit README 等既有技能/文档文本的修改。
