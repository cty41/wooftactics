# 子代理拆分与回执

## 何时拆给子代理

判据是**上下文需求与结果紧凑度**，不是任务大小。反例对照："改一个常量并跑测试"上下文轻、自己干更快（不拆）；"翻两千行构建日志、只要三个失败签名"才是上下文重、结果紧凑（拆）。

该拆：

1. 规格已冻结的机械实现（设计合同 `verified_current`、任务书明确，照图施工）。
2. 上下文重、结果紧凑（日志分诊、OKF 同步链、批量审查、大 diff 归纳）。
3. 纯并行独立调研（用完即弃的探索上下文）。
4. 黑盒验证与独立 review（隔离视角本身是目的）。

不该拆：

1. 与用户的设计收束（grilling/brainstorming/需求澄清）。
2. 计划撰写——写计划的必须看过全部现场。
3. 跨层边界未定、中途必然改方案的开放性改动。
4. 需要完整会话上下文的写入决策（OKF 正文落笔、人工验收账本定性）。

拿不准时默认不拆：主循环串行加载 skill 是安全侧。

## 回执契约

拆出的任务，子代理交回的回执必须包含四段，缺段即不可用。回执以紧凑为默认：证据只贴锚点与要点，不粘贴全量命令输出（主循环需要时自行重跑或查看）。

1. **做了什么**——结论式陈述，不超过 10 行。
2. **证据**——可独立核对的锚点：命令与输出要点、文件路径与行号、哈希、测试计数；纯审查/调研类任务可引用 diff 定位与文件行号代替命令输出。测试计数只有附带命令输出锚点时才算证据，自报计数归入待核验项。
3. **偏差点**——**子代理自身执行**与任务书的差异：范围外改动、被跳过步骤及原因。对被审对象的发现不属此段（那是结论内容，写进第 1 段）。
4. **待核验项**——子代理自认为完成、但主循环必须自己验证的声明清单；无则写"无"。

自我声明不算证据。

## 派发侧义务

派发任务书时给足：工作区路径、任务描述、验收判据、所需验证命令；不传会话历史。任务书含糊导致的返工由派发方负责。

## 主循环义务

收到回执后，对证据锚点至少做一次独立核对（便宜手段：`git diff`、状态查询、抽查命令重跑）；未核对的结论不得直接进入后续步骤。核对与回执不符时，以工作区事实为准并记录差异。

评测运行（`Tools/agent-eval/`）遵循其自身 README，不在本规则约束内。compose-next 的 review 结论格式是本契约在 review 场景的特化，保持不变。

## 示例回执（迷你）

> **做了什么**：修复 `Foo.cs:12` 空引用；补 1 个回归测试。
> **证据**：`git diff --stat` 2 文件 +18/-3；`dotnet test` 412/412 通过；测试名 `FooDoesNotThrowOnNull`。
> **偏差点**：任务书未要求，顺手更新 `Foo.md` 一行文档（未越出文档范围）；未跑统一 verifier（单文件修复，按成本递增止于相关测试）。
> **待核验项**：声称"无其他调用点受影响"——请抽查 `rg "Foo\("` 的调用面。

## 已验证派发配方

### OKF 同步链

机械段对应 `knowledge-maintenance.md` 的第 1、4、5 步：`catalog_impact.py report --worktree` 影响检测 → 按任务书**给定的 scope 清单**逐 scope `catalog_impact.py sync --worktree --scope <scope> --write` 写 metadata → `validate_bundle.py` 校验。其中 `sync --write` 自动写 frontmatter 时间戳/来源指纹与 `log.md` 的 Sync 记录（同日同 scope 为去重替换），属命令固有产出，不算越界。归主循环的是**变更甄别**（第 2 步：对照工作区 diff 判定哪些 scope 属于本任务，剔除无关项后才给出清单）、概念正文落笔（第 3 步）、`catalog-scopes.yaml` 修改，以及 `log.md` 中非 Sync 的知识状态记录；脏工作区下不得同步清单外的 scope。

任务书模板（四要素）：

> 工作区路径：`<repo root>`，当前 workspace checkout。
> 任务描述：执行 OKF 同步机械段（report → 对下列 scope 清单逐 scope sync --write → validate_bundle）。清单：`<scopes>`（主循环变更甄别后给出）。只做这三步，不手动编辑概念正文、`catalog-scopes.yaml`、rules 与 `log.md`；sync --write 自动产出的 metadata 与 Sync 记录除外。
> 验收判据：回执四段齐备；清单内每个 scope 都有 sync 输出锚点，且**无清单外 scope 的 sync 输出**；`validate_bundle.py` 退出码 0。
> 验证命令：`python Tools/okf/catalog_impact.py report --worktree`；`python Tools/okf/catalog_impact.py sync --worktree --scope <scope> --write`；`python Tools/okf/validate_bundle.py`（解释器需含 PyYAML；本机 Windows 用 `py -3`）。

### 门禁日志分诊

机械段：读指定门禁日志 → 产出失败 case 清单与签名锚点（case 名 + 日志行号 + 关键错误行摘要）与批次计数。不修复、不改代码、不重跑门禁。日志必须是真实命令输出（回执记录捕获命令与时间），禁止合成或手写日志。

任务书模板（四要素）：

> 工作区路径：`<repo root>`；日志路径 `<log file>`（只读）。
> 任务描述：对该门禁日志做失败分诊：逐个失败 case 给出 case 名、日志行号锚点与关键错误行摘要；给出各批次通过/失败/跳过计数并与日志汇总行核对。只分诊，不修复、不改代码、不重跑命令。
> 验收判据：回执四段齐备；每个失败 case 附可按行号定位的锚点；计数与日志汇总行一致；记录捕获命令与时间（取自日志头）。
> 验证命令：无执行命令；核对手段是主循环按行号在原始日志抽查 ≥2 处锚点。
