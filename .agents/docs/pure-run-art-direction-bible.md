# Pure Run 项目美术圣经

本文是 Pure Run 静态美术与整体视觉表现的最高层设计契约。具体 Sprite 尺寸与姿态规则继续由 [Pure Run 角色美术指南](pure-run-artwork-guidelines.md) 约束；机器状态、血缘与审核门禁由 [项目级美术方向状态机](pure-run-art-direction-state-machine-design.md) 约束；UI 细则见 [Pure Run UI Design Guide](pure-run-ui-design-guide.md)。下一代生产系统在选择具体 AI 或状态模型前，先以[游戏美术生产第一性原则](game-art-production-first-principles.md)界定运行时玩家信息、角色状态集与验收层次；该 draft 不覆盖本文件的项目视觉权威。

## 一句话方向

**可爱暗黑、英雄卡通；战棋可读性优先；以粗轮廓、大色块、低内部细节和有意留静的构图服务玩法。**

## 六条不可被下层覆盖的视觉支柱

1. **可爱暗黑、英雄卡通。** 亲切和夸张的角色形体可以承载阴森、腐败与危险主题；恐怖主要来自轮廓、节奏、色彩、叙事和行为，不依赖写实血肉。
2. **战棋可读性优先。** 类别、身份、朝向、装备、交互性、路径和危险信息必须先于气氛装饰被读出。
3. **剪影先于细节。** 使用粗而受控的深色轮廓、大色块和通常 2–3 阶硬边明暗。禁止把写实概念插画机械缩小成 Sprite。
4. **注意力有预算。** 每个完整画面只能有一个主焦点，最多两个次焦点；最高亮度、饱和度、轮廓强度、动态和细节密度不得平均铺满画面。
5. **Actor、威胁和交互物突出，场景退后。** 地面与背景主动降低对比、饱和度和高频纹理，为战斗、路径、动作与信息层留静区。
6. **有意设计的手绘感。** 允许克制的不对称、形状夸张和边缘节奏；不接受随机噪点、机械重复、素材拼贴或以“手绘”为不一致辩护。

## 规则层级

```text
项目美术宪法
  → 2D 视觉语法与材质语言
  → 资产家族 Profile
  → 可选 Theme Profile
  → Asset Brief / Scene Brief
  → 候选与固定 Review
```

下层只能具体化或收窄上层。需要破例时必须声明偏离条款、局部范围、理由、证据并获得 `cty41` 明确批准；破例不自动成为全局先例。

当前 Single Pure Run Demo 不预建地区或阵营 Theme Profile。具体任务先使用 Brief；只有同一规则在多个正式场景、多个资产家族中稳定重复后，才允许提炼 Theme Profile。

## 屏幕空间与细节层级

- **一级信息：** 类别、朝向、武器类型、交互性和当前威胁，必须在正常战棋缩放下立即可读。
- **二级信息：** 物种、职业、个体身份和关键材质，在标准角色/物件尺寸下可读。
- **三级信息：** 小装饰、磨损和纹样仅作为近看奖励；消失后不得影响理解，也不能缩小为闪烁、脏边或随机像素。
- 母版放大图不是批准权威。正式 Review 必须同时包含母版、标准尺寸、较小战场尺寸和真实上下文。
- Boss 可以获得更大画面占用和更多二级信息，但一级信息仍必须最先被识别。

## Actor

任何具有身份、意图，并可能参与叙事或战斗的个体都属于 `Actor`。玩家、盟友、中立、敌对、Boss、商人、任务角色和可谈判怪物是可组合表现标签，不是互斥美术家族。

Actor 的识别顺序固定为：

1. 物种与拓扑；
2. 个体性格；
3. 职业与能力；
4. 阵营与文化；
5. 当前敌对、中立、可谈判、受控、狂暴或阶段状态。

世界以动物拟人为主。犬类承担主要英雄与文明视角；猫类是高阶恶魔的重要母题；其他动物形成地区、阵营和职业差异。亡灵与异怪应尽量保留可识别的动物来源。

高阶猫系 Boss 共同保持猫科识别、主动性和聪明感，但可按个体设计为优雅型、阶段变身型或持续狰狞型。威胁不等于“画得更写实”；姿态、眼神、轮廓张力、能力符号和受控 VFX 才是主要威胁语言。

重要 Actor 必须具备叙事可用性：面部方向清楚、眼神可读、静止姿态可表达态度，并能在不改变身份的前提下从战斗转入对话或谈判。

## Equipment 与物品

- 装备首先服务 Actor 身份、动作和战斗可读性，不是独立概念插画。
- 数值稀有度主要由 UI 边框、名称颜色、图标背景和信息层级表达；不得简单用更多雕纹、宝石、反光和常驻 VFX 表示稀有。
- 只有职业标志物、剧情唯一物和会改变角色身份的装备，才允许一个克制的独特世界剪影母题。
- 同一装备共享形制、主色和标志特征，但库存展示与角色实装可以为了屏幕可读性分别简化，不要求机械缩放同一张图。
- 装备单图通过不能代替角色实装通过。正式 Review 必须包含孤立图、128px、目标 Actor 实装、动作/握持层级和同类职责锚点。

## 颜色职责

- Actor 与交互物可以获得较高局部饱和度；场景使用受控、较低对比的底色。
- 危险预警、可操作、治疗、护盾和当前焦点使用稳定语义色域；阵营和地区可以拥有主题色，但不能简单固定为“敌人全红、友军全蓝”。
- 强亮、强饱和与互补色冲突只服务主焦点或短暂状态峰值，不得常驻全屏。

## 形状语言

形状表达气质和状态，不硬编码善恶：

- 圆润：稳定、亲近、笨重或柔软；
- 尖角：张力、速度、危险或警觉；
- 垂直与对称：秩序、权威或克制；
- 断裂与不对称：腐化、失控或衰败。

一个角色、阵营或场景可以混合这些语言。可谈判怪物、堕落英雄和优雅反派不得被“圆=好、尖=坏”的简单规则限制。

## 材质语言

材质通过形状、主色和少量结构符号表达，不追求真实光学：

- **金属：** 基础色、一个硬边阴影块、至多一处受控高光；无连续反射带和环境镜像。
- **木材：** 大色块与少量顺结构线；无密集年轮和随机划痕。
- **皮革：** 主色、包边或接缝之一；无写实毛孔和多层油亮高光。
- **石材：** 大体块、有限裂面和低对比斑块；战斗地面禁止高频碎裂纹铺满。
- **布料：** 清楚折面与少量褶皱方向；无细密织物噪点。
- **毛发：** 以外轮廓毛簇、脸部色块和少量方向性边缘表达；无逐根毛发。
- **骨骼：** 暖冷骨色与大关节形；无湿润写实高光或细密孔洞。
- **玻璃/液体：** 清楚容器与液面符号、有限高光；无真实焦散和复杂折射。

具体色彩由 Asset Brief 或 Scene Brief 决定，但不得改变这些抽象层级。

## World、Prop 与 Interactable

### 地形、建筑与背景

- 先表达可走区域、阻挡、高低差、出口和危险边界，再表达材质。
- 主要战斗地面保持低纹理静区；建筑先有清楚体块、入口和功能，再添加主题装饰。
- 背景不使用比 Actor 更强的轮廓、对比和局部动态。

### 普通 Prop

- 服务尺度、叙事和构图节奏，默认低饱和、低对比、低动画。
- 细节按组聚集，不平均撒满每个 Tile；允许明显留白和重复中的少量变化。
- Hero Prop 也只能成为 Scene Brief 指定的主/次焦点，不能每件都成为 Hero Asset。

### Interactable

- 首先靠造型可供性表达用途，如箱盖、门把、祭坛台面、机关运动方向和商店陈列。
- 常态只比普通 Prop 高一级对比；靠近、悬停或可操作时才允许受控描边、轻量动态和 UI 提示。
- 禁止用永久发光证明“能点”，也不把所有交互物涂成同一种高饱和颜色。

## Scene Brief 与审美克制

特殊事件、Boss 关和重要叙事场景必须声明：

- 玩法流程与叙事节拍；
- 一个主焦点和最多两个次焦点；
- 玩家视线、移动路径和必须留静的区域；
- Actor 出场、对话/战斗状态与交互物发现顺序；
- 当前场景局部配色、形状、材质与装饰密度；
- 光照/VFX 强调时点和主要战斗地面的可读性预算；
- 模块化资产、专属 Hero Asset 与禁止堆料区域。

普通地图可以复用结构模板；特殊事件和 Boss 关必须重新进行构图审核，不能通过增加更多 Prop 和特效替代概念设计。

## 表现层基线

- VFX 区分预警、发动、命中和消散；危险范围与伤害时点先于华丽程度。
- 常态特效不得持续遮住 Actor 脸部、脚底、Tile 边界和交互物；大面积强亮仅用于短暂峰值。
- 基础光照烘焙进 2D 美术；动态光只用于法术、危险、选中和剧情焦点的局部强调，不重新染毁 Actor 固有色。
- 镜头保持固定等距投影、可预测缩放和稳定战场阅读。Boss/事件表演运镜在后续专项中设计，本文件不授权运行时实现。
- 动画先保证关键姿态剪影、前摇/命中/恢复节奏和静止帧可读。

## 明确禁止

- 写实或半写实材质混入卡通角色；
- 雕纹、包件、微高光和纹理噪声堆积；
- 角色/装备靠表面细节而非轮廓识别；
- 所有区域同时高对比、高饱和、高动态；
- 以“高级”“Boss”或“稀有”为理由无上限增加复杂度；
- 单图看似漂亮但放进角色或场景后媒介割裂；
- 用自动指标、Agent 报告或技术通过冒充人工审美批准。
