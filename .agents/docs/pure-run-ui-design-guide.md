# Pure Run UI Design Guide

本文记录已确认的 UI 方向和功能宪法。它不表示正式 UI 皮肤、字体、图标、动效或 Godot HUD 已实现；当前运行时继续使用测试占位字体。任何 UI 运行时改动必须另行授权、设计和验证。

## 目标

**克制、不喧宾夺主、强调服务功能，并保留少量属于 Pure Run 的可爱暗黑手绘表现。**

UI 的第一职责是帮助玩家理解状态、完成决策和返回游戏，而不是证明面板本身有多华丽。

## 参考职责

### 《轩辕剑 3》

只提取：

- 小确认框只承载一个决定；
- 属性升级直接显示“当前 → 新值”；
- 深色半透明面板保留场景上下文；
- 少量暖金用于标题和当前项。

不提取：

- 东方卷轴、书法和符箓身份；
- 暗到难读的未选中文本；
- 仅靠颜色表达选中；
- 穿过正文与控件的明显背景纹样。

### 《暗黑 2 重制版》

只提取：

- HUD 与系统页位置稳定；
- Chrome 与内容区职责分离；
- 角色、技能、任务和背包具有清楚网格与层级；
- 大系统页可以停靠边缘并保留一部分世界上下文。

不提取：

- 写实石材、雕像、重哥特雕花和多层厚框；
- 与内容权重相近的高密度 Chrome；
- 过多细长装饰字体；
- 默认同时打开多个大型系统面板。

参考截图位于用户本机，只作为第三方观察材料；仓库不得复制图片或保存绝对目录。需要登记时只保留来源标签、文件名、SHA-256 和参考职责。

## Pure Run 表皮方向

未来原型以“深色半透明墨色面板＋细暖金边＋轻微手绘不规则感”为首选方向：

- 内容区接近黑色，但可根据任务保留少量场景上下文；
- 边框细而清楚，不使用写实石材或复杂浮雕；
- 暖金只承担标题、当前焦点与关键确认；
- 常规界面只用细边、色块、排版和图标；
- 角色页、背包、Boss/事件选择等关键页面最多允许一个低对比主题母题，且只能位于标题、边角或空白区。

这一表皮尚未原型验证，不得据此直接替换运行时 UI。

## 功能宪法

1. **默认让位给游戏画面。** 常驻 HUD 只显示当前回合、资源、行动和生存所需信息。
2. **一次界面只解决一个任务。** 简单确认不同时展示完整角色百科；升级界面直接显示变化。
3. **位置稳定。** 生命、技能、回合、确认和关闭等高频功能跨界面保持稳定逻辑位置。
4. **渐进披露。** 第一层显示名称、图标、关键数值和操作；说明、公式与背景故事进入悬停或展开层。
5. **状态不能只靠颜色。** 选中、禁用、危险和增减同时使用轮廓、图标、形状或文字。
6. **装饰只占 Chrome。** 纹样和动物母题进入标题、角标、边框与空白区；正文、数值表和格子背景保持安静。
7. **强调短暂且分级。** 全屏不能同时出现多个强发光焦点。
8. **动效解释状态。** 开合、选中、数值变化和错误反馈可以有短促动画；禁止无功能持续飘光和呼吸边框。
9. **关键系统页按任务决定是否保留世界上下文。** 不强制所有页面透明覆盖，也不默认全部切成全屏。
10. **文本优先于纹理。** 背景图案不得穿过文字、图标和点击目标。

## 等距战场四角分区

默认以等距地图外围安全区组织 HUD：

- **左上：** 当前 Actor、HP/MP、特殊资源和状态摘要；
- **右上：** 回合、先攻队列、当前目标与关卡目标；
- **左下：** 选中对象详情、悬停说明、队伍切换或低频上下文操作；
- **右下：** 当前动作、确认/取消和结束回合等高频决策。

屏幕中心与等距菱形的主要可走区域保持干净；底部中央只允许短暂提示，不默认铺设宽 Action Bar。该分区是后续原型起点，不授权立即调整现有 Godot HUD。

## 文字与图标

未来方向为“易读正文＋克制标题字＋图标辅助”：

- 正文、数值、按钮、任务和词条使用清晰中文字体；
- 标题可以使用略有手绘/奇幻气质的展示字，但不进入大段正文；
- 图标帮助定位，首次出现的重要机制仍配合名称或文字；
- 数值比较优先使用稳定宽度与明确对齐；
- 当前继续使用测试占位字体，不新增字体资产。

## 语义色

- 生命、伤害与危险：红；
- 魔力：蓝或青；
- 恢复与安全：绿；
- 当前焦点与确认：暖金。

常态颜色压低，变化和操作峰值才提高亮度。颜色不得独自承载含义；必须配合形状、图标、文字或位置。

## 交互状态

- `Normal`：低对比深色底与清晰标签；
- `Hover`：提高局部边线和文字亮度，可有一次短进入动效；
- `Focus`：在 Hover 之外增加明确外轮廓或角标；
- `Selected`：暖金细框和稳定形状标记，不持续强发光；
- `Pressed`：轻微内压、变暗或边框收缩；
- `Disabled`：降饱和但保持可读，悬停解释原因；
- `Dangerous`：仅在确认阶段使用红色，并明确写出结果；
- `New/Changed`：一次短促脉冲或小标记，查看后回归常态。

《轩辕剑 3》的荧光绿目标描边只证明“状态必须明确”，不作为 Pure Run 的直接色彩方案。

## 界面深度

- 战斗 HUD、悬停信息：贴边或局部；
- 简单确认、事件选择：小型模态框并保留场景；
- 角色、装备、技能树等高信息系统页：可以使用大面板或全屏；
- 是否保留中间世界视野由当前任务决定，不把任何一种布局强制用于全部页面。

## 后续独立工作边界

以下内容需要用户提供更多参考并进行实际原型比较后才能决定：

- 正式中文字体与标题字体；
- 面板透明度、边框宽度、圆角/折角和纹理强度；
- 正式图标语言；
- 动效时长、缓动和音效配合；
- 四角布局在真实战场、不同分辨率和本地化文本下的安全区；
- Godot Theme、Control、HUD 和系统页实现。

这些是明确延期的独立工作，不属于当前项目级美术状态机实施范围。
