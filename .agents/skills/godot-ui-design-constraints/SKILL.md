# Godot UI 设计约束

玩家界面要守住下面这些不变量。某次界面上的字号、坐标和对比度比值会随改动失效，写在当次代码里，不写进本技能。

## Quick Reference

| 要守住的 | 做法 |
|---|---|
| 字号 | 只用 `GodotTacticsTheme.FontSizeScale`；已有偏离用 `SnapFontSize` |
| 间距 | 界面间距只用 `SpacingScale` |
| 对比度 | 按文字真正压住的底算，不按面板底色代替 |
| 主按钮 | 一屏只有一个主动作用主按钮变体 |
| 状态 | 种类和状态要能靠形状或文字认出来 |
| 布局合同 | 为了防止已知错位而保留的布局，优先于“禁止绝对坐标” |
| 让出画面 | 盖在地图上的面板不横贯窗口，宽度跟内容或一个够读的固定宽度走 |
| 文字不出框 | 文字在自己的面板里换行，面板高度跟着文字变 |
| 新观察 | 进游戏看过、而且以后还会再犯，才补一条原则 |

## When to use

- 改主菜单、营地、战斗 HUD、路线图、结算、背包或暂停的界面。
- 新建一个玩家能看到的控件。
- 想把一次审查里的具体尺寸写进规则之前。

调试夹具、作弊控制台和编辑器工作台不用这套。设计指南里的暖金表皮、九宫格和正式字体还没验证，不要据此换皮。

## Workflow

### Step 1: 先用档位

新的文字和界面间距取主题里的档位。不要为某一个屏幕再发明一档。

```csharp
label.AddThemeFontSizeOverride("font_size", GodotTacticsTheme.SnapFontSize(size));
row.AddThemeConstantOverride("separation", GodotTacticsTheme.SpaceSm);
```

### Step 2: 一屏一个主动作

同一屏里向前的那一个动作用主按钮。其余用次按钮、紧凑按钮或行动按钮。同级选项（一排技能、一排商品）都是次级，不再各做一个主按钮。

### Step 3: 对比度看真正的底

文字压在色条、圆点或战场上时，用那块底色判断能不能读。不要拿面板底色代替，否则检查会误报通过。

### Step 4: 给游戏画面留位置

盖在地图或战场上的面板靠屏幕边留出空隙。宽度跟内容走，或用一个够读的固定宽度。不要把一条横栏铺满窗口，否则会挡住角落里的地图内容。没有地图在后面的整页（背包、结算）可以继续用宽页眉。

### Step 5: 文字留在面板里

说明文字放进它所属的面板，默认自动换行。面板高度跟着换行后的文字变。不要给文字一个画到框外的固定区域。

```csharp
label.AutowrapMode = TextServer.AutowrapMode.WordSmart;
```

### Step 6: 进游戏再加原则

调整做完后由人进游戏看。只有看完仍然成立、而且下一张界面还会再犯的问题，才在这里加一条不变量。只出现一次的尺寸留在当次修改里。

## Anti-patterns

| 错误 | 正确 | 原因 |
|---|---|---|
| 把当前文件的字号和坐标抄进技能 | 只写要守住的不变量 | 下次一改，抄来的数字就错了 |
| 没进游戏就宣布新原则 | 先改，再看，再决定收不收 | 代码里看起来的问题，画面上可能不是问题 |
| 用间距档位去改地图层距和车道距 | 玩法几何保持原样 | 那是路线结构，不是界面留白 |
| 为了“不要绝对坐标”拆掉已有的对齐合同 | 先保住不会错位的布局 | 自动排版曾经让头像跟着行数变高变矮 |
| 按未验证的表皮指南整页换色 | 沿用现在的主题色 | 暖金细边和九宫格还没有原型 |
| 地图上的说明栏铺满窗口 | 宽度跟内容或一个够读的固定宽度走 | 空面板会挡住角落里的游戏内容 |
| 文字用固定区域画到面板外面 | 在面板内换行，高度跟着变 | 句子超出所属面板就读不成一块 |

## Checklist

- [ ] 新文字和界面间距落在档位里
- [ ] 这一屏只有一个主按钮
- [ ] 文字对比度按它压住的底判断
- [ ] 没有把某次界面的当前像素写进本技能
- [ ] 盖在地图上的面板没有横贯窗口
- [ ] 说明文字在自己的面板里换行，面板高度跟着文字
- [ ] 没有换皮、没有新增字体
